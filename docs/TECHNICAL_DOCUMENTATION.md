## 1. 项目概述

**铁甲战棋** 是一款基于浏览器的三维回合制策略战棋游戏，包含两个核心游戏模式：

- **战术模式（Tactical）**：16×12 格子地图，红蓝两方各控制多个独立单位（坦克、步战车、火炮等），玩家逐个操作单位进行移动、攻击、修建工事、潜行等行动。
- **战略模式（Strategic）**：10×8 格子地图，双方控制的是由多种单位编组而成的「部队」（如装甲营、机械化步兵营等），在更大的地图上进行战略机动和战斗。

游戏支持预设地图模板（山地隘口、河谷突破、城市攻防、沙漠风暴）和程序化地图生成（基于风蚀模拟）。包含英雄系统、天气系统、士气系统、地雷系统、据点占领、增援系统等丰富玩法。

## 4. 地图系统

### 4.1 地图基础

战术地图尺寸为 **16×12** 网格（`MAP_WIDTH=16`, `MAP_HEIGHT=12`），采用 2D 数组结构：

```typescript
interface GameMap {
  width: number;       // 16
  height: number;      // 12
  cells: MapCell[][];  // cells[z][x] - Z 轴为行，X 轴为列
}
```

每个格子 `MapCell` 包含：

```typescript
interface MapCell {
  position: Position;      // { x, z }
  terrain: TerrainType;    // 地形类型
  unit: Unit | null;       // 驻守单位
  fortified: boolean;      // 是否有工事
  fortifiedByTurn?: number; // 工事修建的回合数
  fortifyDuration?: number; // 工事持续时间
  capturePointId: string | null; // 据点引用
  hasMinefield?: boolean;  // 是否有地雷
  minefieldOwner?: Faction; // 地雷所属方
}
```

|------|--------|----------|----------|--------|------------|------|
| `plains` | 平原 | 1 | 0 | ✅ | ✅ | `#7cb342` |
| `forest` | 森林 | 2 | +15 | ✅ | ✅ | `#2e7d32` |
| `mountain` | 山地 | 3 | +25 | ✅ | ❌ | `#78909c` |
| `water` | 水域 | 99 | 0 | ❌ | ❌ | `#1565c0` |
| `city` | 城市 | 1 | +20 | ✅ | ✅ | `#8d6e63` |
| `road` | 公路 | 0.5 | -5 | ✅ | ✅ | `#9e9e9e` |

### 4.3 地图生成方式

游戏支持 **6 种地图类型**（`MapType`）：

#### 4.3.1 随机地图 (`random`)

生成流程：
1. 按权重随机分配地形（`TERRAIN_WEIGHTS`: 平原 30、森林 18、公路 12、山地 8 等）
2. 添加道路网络（水平+垂直主干道+随机辅助道路）
3. 在水域上自动放置桥梁
4. 在道路交汇处放置城市（相邻道路≥3 时 40% 概率）
5. 在地图中部随机放置要塞
6. 确保边缘部署区域可通行

#### 4.3.2 山地隘口 (`mountain-pass`)

- 中间 4 行（z=4~7）为不可穿越的山脊
- 仅两个隘口可通过（z=4~5 的 x=3~4 和 z=6~7 的 x=11~12）
- 两侧添加森林和通往隘口的道路
- 强制争夺通道的战术地图

#### 4.3.3 河谷突破 (`river-valley`)

- 中间两行（z=5~6）为河流（水域）
- 三座桥梁位于 x=2、x=7、x=12
- 南北两岸有森林，桥头有城市
- 必须争夺桥梁控制权

#### 4.3.4 城市攻防 (`urban-warfare`)

- 中央密集城市群（x=5~10, z=3~8）
- 核心要塞 2 座
- 十字主干道+放射状道路
- 城市提供高防御加成（+20）

#### 4.3.5 沙漠风暴 (`desert-storm`)

- 全图沙漠为底色
- 中央 4 格要塞群为核心
- 要塞外围城市环
- 8 处绿洲（森林）散布角落
- 少量沙丘（山地表示）

#### 4.3.6 程序化地形 (`procedural`)

基于风蚀模拟的程序化生成系统，详见 [程序化地图生成](#44-程序化地图生成)。

### 4.4 程序化地图生成

位于 `src/game/procedural-map.ts`，实现了一个完整的 **7 阶段地形生成管线**：

#### 阶段 1: 多倍频噪声基础高度图 (fBm)

使用自实现的 **Perlin 噪声**（无外部依赖）：
- 256 大小的排列表，12 个梯度方向
- 6 层倍频叠加（persistence=0.5, lacunarity=2.0）
- 尺寸自适应缩放 `baseScale = 3.0 / max(width, height)`
- 加入"扭曲"噪声增加自然感
- 边缘渐变形成"岛屿感"

#### 阶段 2: 风蚀模拟

核心创新算法，模拟风吹沙粒形成沙丘的过程：
- 根据主导风向确定迎风边缘
- 每次迭代发射 `max(width,height) * 2` 个粒子
- 粒子沿风向移动，带有湍流扰动
- 上坡沉积、洼地侵蚀
- 坡度超过临界角（0.08）时粒子停止
- 迭代 40~100 次（根据地图尺寸自适应）

#### 阶段 3: 海平面判定

- 统计高度图直方图分布
- 海平面设在第 28 百分位
- 约 22%~30% 区域成为水域

#### 阶段 4: 河流生成

- 从最高非水域格子选择源头
- **最陡下降路径追踪**：每步移动到 8 邻域高度最低的邻居
- 沿途雕刻河道（降低高度 0.04）
- 河岸效果（两侧降低 0.012）
- 多条河流之间保持最小间距

#### 阶段 5: 生物群落分配

基于高度+湿度+温度的综合判定：
- **湿度场**：多源 BFS 计算到最近水域的距离，指数衰减
- **温度场**：纬度映射 + 海拔降温
- 生物群落规则：
  - 低于海平面 → water
  - 极高海拔 → mountain
  - 低海拔+干燥 → desert
  - 低海拔+潮湿+温暖 → forest
  - 近水+平坦+潮湿 → swamp

#### 阶段 6: 城市与基础设施

- **城市选址**：综合平坦度、近水性、中心性评分
- **公路生成**：A* 算法连接城市，遇到水域自动架桥
- **要塞放置**：在城市附近制高点

#### 阶段 7: 边缘通行处理

- 确保左右边缘列（部署区）无水域/山地/沼泽

### 4.5 分层地图生成系统

支持 **16 种地形模板** 的多尺度生成：

```typescript
type TemplateType =
  | 'city_block' | 'forest_road' | 'forest_rail' | 'industrial_zone'
  | 'farmland' | 'dense_forest' | 'mountain_range' | 'river_delta'
  | 'coastal_city' | 'desert_oasis' | 'plains_village' | 'swamp_wetland'
  | 'fortress_hill' | 'crossroads' | 'open_plains';
```

生成流程：
1. 使用 Perlin 噪声生成宏观属性场（高度+湿度）
2. 对每个宏观格子进行加权随机模板选择（考虑邻居兼容性）
3. 宏观平滑后处理减少"孤岛"效应
4. 展开模板为微观地形网格
5. 边缘通行处理

战术尺度：3×2 宏格 × 8×8 → 24×16 地图
战略尺度：12×9 宏格 × 8×8 → 96×72 地图

### 4.6 战略地图

战略模式使用 **10×8** 格子地图：

```typescript
interface StrategicMap {
```

### 5.3 单位特殊机制

#### 潜行系统

可潜行的单位：`scout`（2 回合）、`infantry`（3 回合）、`engineer`（2 回合）

```typescript
interface Unit {
  isStealthed: boolean;          // 是否处于潜行状态
  stealthCooldown: number;       // 潜行冷却剩余回合
  stealthTurnsRemaining: number; // 潜行持续回合
}
```

- 潜行时单位不被敌方检测到（不阻挡移动、不出现在敌方视野）
- 在特定地形（森林+30、要塞+25、城市+20、沼泽+15、山地+10）潜行时获得额外占领进度
- 退出潜行后有冷却回合（侦察车 3、步兵 4、工程车 5）

#### 弹药系统

有限弹药单位：
- 自行火炮：4 发
- 防空导弹车：5 发
- 武装直升机：6 发
- 火箭炮：3 发

补给车可为相邻友军补充弹药（每次 2 发）。

#### 直升机特殊规则

- 忽略所有地形移动消耗（统一消耗 1）
- 可以飞越山地、沼泽等不可车辆通行地形
- 不能在水域上降落
- 沙暴天气下无法起飞

战略部队战斗力计算：
- 攻击力 = Σ(单位攻击 + 单位穿甲 × 0.3) × 数量
- 防御力 = Σ(单位防御 + 单位装甲 × 0.4) × 数量

## 6. 战斗逻辑

### 6.1 伤害计算公式

```typescript
// 基础伤害
let damage = attacker.stats.attack - defender.stats.defense;

// 地形防御加成
damage -= terrainDefenseBonus;

// 工事防御加成 (+20)
if (cell.fortified) damage -= FORTIFY_DEFENSE_BONUS;

// 士气修正
if (attackerMorale >= 80) damage *= 1.1;  // 高士气 +10%
else if (attackerMorale <= 40) damage *= 0.9;  // 低士气 -10%

// 天气修正
damage *= weatherConfig.attackModifier;

// 英雄被动技能修正
// (如铁壁·赵虎的固定减伤 8 点)

// 最小伤害保护
damage = Math.max(damage, 1);
```

### 6.2 装甲与穿甲

穿甲值用于忽略目标装甲：

```
effectiveArmor = defender.armor - attacker.armorPenetration
if (effectiveArmor > 0) damage *= (1 - effectiveArmor * 0.01)
```

两种伤害类型：
- **动能武器（kinetic）**：坦克、步战车、直升机 - 对抗装甲目标效果好
- **高爆武器（he）**：火炮、火箭炮 - 对轻装甲和无装甲目标效果好

### 6.3 反击系统

被攻击的单位会自动反击（如果存活且在攻击者射程内）：
- 反击伤害 = 正常攻击伤害（使用防御方的攻击力计算）
- 反击不消耗行动

### 6.4 战斗结果通知

```typescript
interface CombatToast {
  id: number;
  attackerName: string;
  defenderName: string;
  attackerFaction: Faction;
  damage: number;
  defenderRemainingHp: number;
  counterDamage?: number;
  attackerRemainingHp?: number;
  wasKill: boolean;
  wasCounterKill?: boolean;
  attackerKillCount?: number;  // 连杀计数
  defenderType?: UnitType;
  timestamp: number;
}
```

连杀通知：
- 2 杀：双杀 ✨
- 3 杀：三杀 ⚔️
- 4 杀：四杀 🔥
- 5 杀：无双 💀

### 6.5 移动与寻路

使用 **BFS（广度优先搜索）** 计算可移动位置：
- 支持 4 个基本方向（上/下/左/右）
- 考虑地形移动消耗
- 考虑天气移动修正
- 友方单位阻挡移动
- 未检测到的潜行敌方单位不阻挡移动（防止信息泄露）

### 6.6 移动动画


## 8. 战略模式

### 8.1 概述

战略模式是更高层次的战斗抽象，玩家操作的是**部队编制**而非单个单位。

### 8.2 游戏流程

1. **部署阶段**：在预算（100 点）内选择部队编制部署到指定区域
2. **选择部队**：点击己方部队查看可移动/可攻击区域
3. **移动部队**：选择目标扇区移动（考虑地形消耗）
4. **攻击**：移动到相邻敌方扇区触发战斗
5. **结束回合**：切换双方行动

### 8.3 战略战斗解析

战斗结果基于攻防力对比 + 随机因子：

```typescript
effectiveAttackerPower = attackerPower * (0.8 ~ 1.2 随机)
effectiveDefenderPower = defenderPower * (0.8 ~ 1.2 随机)
```

| 战况 | 结果 | 攻方损失 | 守方损失 |
|------|------|----------|----------|
| 攻方 > 守方 × 1.3 | 攻方大胜 | 5~20% | 60~90% |
| 攻方 > 守方 | 攻方险胜 | 15~35% | 40~70% |
| 守方 > 攻方 × 1.3 | 守方大胜 | 60~90% | 5~20% |
| 守方 > 攻方 | 守方险胜 | 40~70% | 15~35% |
| 接近平手 | 平局 | 35~60% | 35~60% |

### 8.4 战略增援

- 每 6 回合获得一次增援
- 每方最多 3 次增援
- 增援部队：机械化步兵营编制
- 优先在己方部队附近生成

### 8.5 战略 AI

AI 根据难度参数执行行动：
- **简单**：50% 随机移动，40% 随机攻击，10% 跳过攻击
- **普通**：15% 随机移动，10% 随机攻击，1% 跳过攻击，偏好弱目标
- **困难**：0% 随机性，100% 最优决策

AI 位置评估考虑：
- 地形防御加成
- 城市战略价值
- 友军编队距离
- 敌军威胁/机会
- 部队类型特性（炮兵后撤、侦察前压、防空靠近友军）

### 8.6 战略-战术集成

战略模式下的战斗可以切换到战术模式进行详细操作：

```typescript
// 战略地形 → 战术地图类型映射
plains/highland → random
forest/mountain → mountain-pass
city → urban-warfare
desert → desert-storm
water/marshland → river-valley
```

战术战斗结果回传到战略模式：
- 统计各方存活单位数量
- 更新战略部队的剩余编制
- 判定胜负并更新战略地图状态

## 9. AI 系统

### 9.1 战术 AI

位于 `src/game/ai.ts`，包含以下功能：

#### 攻击决策

AI 评估所有可攻击目标，选择最佳目标：
- 计算击杀概率（`calculateKillProbability`）
- 评估反击伤害
- 期望伤害 = 击杀概率 × 击杀价值 + 非击杀伤害 - 反击伤害

#### 移动决策

- 优先攻击可击杀目标
- 次优先攻击高价值目标（火炮、火箭炮优先）
- 考虑地形防御加成
- 向敌方阵地推进

#### 难度影响

- **简单**：随机选择，偶尔跳过行动
- **普通**：基本战术逻辑，小概率随机
- **困难**：最优决策，动态难度调整

### 9.2 动态难度调整

```typescript
interface AIDynamicDifficulty {
  enabled: boolean;
  currentDifficulty: AIDifficulty;
  metrics: {
    playerKillRatio: number;         // 玩家击杀比
    playerDamageEfficiency: number;  // 玩家伤害效率
    turnsElapsed: number;            // 已进行回合数
    lastAdjustTurn: number;          // 上次调整回合
    adjustmentCount: number;         // 调整次数
  };
}
```

根据玩家表现自动调整 AI 难度。

### 9.3 AI 执行延迟

AI 行动之间有延迟（`AI_DELAY`）以增强可观察性：
- 移动延迟
- 攻击延迟
- 回合切换延迟

### 15.1 据点类型

| 类型 | 中文名 | 占领阈值 | 占领半径 | 提供视野 |
|------|--------|----------|----------|----------|

### 15.2 占领机制

- 单位在据点附近（占领半径内）停留时，每回合增加占领进度
- 双方同时占领时，进度相互抵消
- 进度达到阈值时完成占领
- 占领后为所属方提供视野加成

### 15.3 潜行占领加成

潜行单位在特定地形上获得额外占领进度：
- 森林：+30/回合
- 要塞：+25/回合
- 城市：+20/回合
- 沼泽：+15/回合
- 山地：+10/回合

## 22. 性能优化

### 22.1 React 渲染优化

- 使用 `useShallow` 选择器避免不必要的重渲染
- **关键规则**：避免在 `useShallow` 选择器中使用数组操作（`.filter()`、`.sort()`、`.map()`），这会导致无限重渲染循环。将数组计算移到 `useMemo` 中。

### 22.2 状态更新优化

- 不可变状态更新（浅拷贝嵌套对象）
- 使用 `crypto.randomUUID()` 防止单位 ID 冲突
- 深拷贝单位时注意嵌套对象（`stats`、`abilities[].effect`）

### 22.3 寻路优化

- 使用 `Set` 进行 O(1) 去重（替代 O(n²) 的 `some()`）
- 使用索引-based 队列替代 `shift()` O(n)
- 预计算邻居列表

### 22.4 渲染优化

- Three.js 实例化渲染（相同几何体共享）
- 按需更新（只更新变化的网格）
- 迷雾系统使用 unit visibility 而非 ground overlay（性能更好）

### 22.5 内存管理

- 战斗日志限制 100 条（自动裁剪）
- 单位行动历史保留最近 50 条
- 回合总结限制数量
